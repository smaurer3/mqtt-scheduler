What is MQTT Scheduler?

MQTT Scheduler watches a Google Calendar and automatically publishes MQTT messages at the start and end times of calendar events. Each event's description lists scenes to run — a scene is a named set of MQTT topic/payload pairs defined in this app.

The green badge in the top-right shows whether the MQTT broker is reachable. Red means the Pi cannot currently connect to the broker.

Scenes

A scene is a named group of MQTT actions. Each action has:

  • Topic — the MQTT topic to publish to (e.g. home/lights/main)
  • Payload — the message to send (e.g. ON, 255, {"state":"on"})
  • Delay (s) — seconds to wait before this action runs (useful for staggering)
  • Order — actions run lowest-order first within a scene

Use the ▶ Run button on any scene to trigger it immediately for testing.

Calendar Event Descriptions

Add scene triggers to a Google Calendar event by putting them in the event's description, one per line. Any line that doesn't match the format is ignored, so you can still include notes.

Format When it runs
START:Sunday MorningExactly at event start time
END:Sunday ShutdownExactly at event end time
-30 START:Pre-service Setup30 minutes before event start
+15 END:Cleanup15 minutes after event end
-240 START:HVAC Preheat4 hours before event start

Scene names are case-insensitive — sunday morning and Sunday Morning both match the same scene.

Once a trigger runs, its line is marked ✓ in the calendar description so it never runs twice, even if the poller checks again.

A full example description:

-30 START:HVAC Preheat
START:Sunday Morning
END:Sunday Shutdown
+10 END:HVAC Off

Macros

A macro is a named group of scene triggers — each entry specifies a trigger type (START or END), an offset in minutes, and a scene name. Instead of listing every scene individually in a calendar event, you put a single macro reference and it expands automatically.

Calendar syntax:

Format What it does
MACRO:StandardExpands all entries (START and END) from the "Standard" macro

When the poller first sees a MACRO: line it replaces it with all the macro's constituent trigger lines (e.g. -30 START:HVAC Preheat, END:Sunday Shutdown) directly in the calendar event description. Those lines then run and get ✓'d one by one as normal. The START/END on each macro entry determines which event time it fires relative to.

Example — a macro called Standard with these entries:

START  -30 min  HVAC Preheat
START    0 min  Sunday Morning
END      0 min  Sunday Shutdown
END    +10 min  HVAC Off

A calendar event with just:

MACRO:Standard

…expands on first poll to:

-30 START:HVAC Preheat
START:Sunday Morning
END:Sunday Shutdown
+10 END:HVAC Off

Valid Event Titles

The Valid Event Titles list in Settings acts as a filter — the poller only processes events whose title exactly matches one of the listed names (case-insensitive). Events with any other title are silently ignored.

This allows multiple Pi instances to share the same Google Calendar without interfering:

  • Church Pi — Valid titles: Sunday Meeting, Wednesday Meeting, Fast, Open Night
  • Camp Pi — Valid titles: Camp Meeting, Supper, Camp Activity

Leave the list empty to process every event in the calendar regardless of title.

How the Poller Works

  • Runs automatically every 5 minutes via a cron job on this Pi
  • Fetches events from Google Calendar up to Max Offset hours ahead and behind
  • Finds any START: / END: lines whose calculated fire time falls in the next 5 minutes
  • Sleeps until the exact fire time, then publishes all MQTT actions in the scene
  • Updates the calendar event description with ✓ so it doesn't run again

Poller output is logged to /home/pi/calcontrol/poller.log on the Pi.
